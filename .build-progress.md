## Build workarounds

- `-DPython3_EXECUTABLE` is ignored: Pulse's top-level CMakeLists calls
  `remove_cmake_variables(Python3_)` before `find_package(Python3)`. Use
  `-DPulse_PYTHON_HOME_DIR=<venv>` (forwarded to the Innerbuild) plus
  `VIRTUAL_ENV=<venv>` in the environment. Configure:

  ```bash
  VIRTUAL_ENV=$PWD/.venv cmake --fresh -S ../engine -B .pulse-build \
    -DCMAKE_BUILD_TYPE:STRING=Release -DPulse_PYTHON_HOME_DIR=$PWD/.venv \
    -DPython3_FIND_VIRTUALENV=ONLY \
    -DPulse_JAVA_API=ON -DPulse_PYTHON_API=ON -DPulse_GEN_DATA=ON
  VIRTUAL_ENV=$PWD/.venv cmake --build .pulse-build -j 12
  ```

- process-bigraph 1.10 / bigraph-schema 1.8.2 drop `initial_state()` values on
  `overwrite[float]` and `boolean` output ports (the filled schema default wins
  in `Composite` init's `combine`). Upstream behavior, not patched here.
  Design consequence: vitals are plain `float` ports emitting deltas against
  the previous Pulse reading (seeded by `initial_state()`), and the death flag
  is `irreversible_state` (correct initial value == default False).
  Regression test: `tests/test_composites.py::test_first_emitted_row_carries_loaded_vitals`.
  Minimal repro (prints `float {'x': 42.0}`, `overwrite[float] {'x': 0.0}`,
  `maybe[float] {'x': 42.0}`; `boolean` with initial True prints False):

  ```python
  from process_bigraph import Process, Composite, allocate_core
  for typ in ('float', 'overwrite[float]', 'maybe[float]'):
      class P(Process):
          def inputs(self): return {}
          def outputs(self): return {'x': typ}
          def initial_state(self): return {'x': 42.0}
          def update(self, s, i): return {}
      core = allocate_core(); core.register_link('P', P)
      sim = Composite({'state': {'p': {'_type': 'process', 'address': 'local:P',
                                       'outputs': {'x': ['s', 'x']}}}}, core=core)
      print(typ, sim.state['s'])
  ```
- GNU `timeout` is not on macOS; run probes without it (each well under 120 s).
